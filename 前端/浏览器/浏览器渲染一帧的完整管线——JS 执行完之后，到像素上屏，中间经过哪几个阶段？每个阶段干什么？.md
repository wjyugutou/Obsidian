
1. Style 样式计算：CSS 匹配 + 级联，算出每个元素的最终样式
2. Layout 布局：计算所有元素的几何位置（宽高、偏移）——这就是回流
3. Paint 绘制：栅格化，把元素画成像素（背景、文字、边框、阴影）
4. Composite 合成：合成器线程把各图层合成，GPU 上屏

浏览器渲染里，线程分工是——主线程：JS + 样式 + 布局 + 绘制；合成器线程：合成 + 滚动 + transform/opacity 动画。记死这张分工表

### 在 死循环里 操作transform 元素里的文字

文字会永远停在旧内容，但 transform 动画（如果同时在跑）还在动.

如果是 ` while(true) {操作dom 文字}`, DOM 其实改动了，但屏幕上一个字都不会变。

1. 改文字 = 图层内容变化 → 需要重新算样式、布局、生成新的 paint 指令——这三步全在主线程
2. 主线程被死循环占死 → 这三步永远排不上 → 新贴图永远栅格化不出来
3. 合成器线程手里拿的还是旧贴图，它只负责矩阵变换——它不知道（也无权知道）文字变了
4. 最终现象：动画继续动，但动的还是旧文字的那张贴图；文字冻结、交互冻结、输入冻结


这也解释了业界一个设计：*"内容每帧都在变的动画"（数字滚动、进度条、加载动画）不用 CSS 动画做，而用 canvas*——因为内容更新逃不开主线程。真正的终极解法是 OffscreenCanvas：在 worker 线程里绘制内容，把帧直接交给合成器线程——内容更新也搬到主线程之外。这是浏览器渲染的高阶彩蛋，面试答出来是加分项
