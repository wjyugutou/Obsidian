
React 同时维护两棵 fiber 树

## 一、为什么要两棵树（双缓冲）

React 渲染分两个阶段：render（reconcile）——可中断，commit——不可中断。
- current：当前屏幕上展示的树
- workInProgress：这次渲染正在构建的新树

为什么必须两棵？因为 render 阶段随时可能被打断（这就是 React 18 并发的实现基础——比如用户输入的高优先级任务插队，渲染线程就要让位）。如果 React 在唯一一棵树上边改边展示，改到一半被打断——屏幕上的树就是残废的。所以新内容全部在 workInProgress 上构建，构建完，commit 时整体切换（current.alternate 互相指向），一次换血。类比：GPU 双缓冲、游戏引擎的一帧构建——同一个思路。

### reconcile 具体干什么

从根 fiber 开始，重新执行组件函数产出新的 element 树，然后 diff——能复用的 fiber 节点（type + key 匹配）直接复用其 DOM，只标出真正变化的节点，构建出 workInProgress 树。不是重建一棵树，是打补丁式更新。
