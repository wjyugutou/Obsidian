Vue3 的 diff，两步：
1. 预处理：先从头、从尾跳过公共前缀/后缀（同 key 直接复用，不进入核心 diff）。头部插入、尾部插入、顺序没变——这三种常见场景在预处理就被解决，根本不走算法。
2. 中间乱序部分：
- 建 newIndexToOldIndexMap：新节点在新列表的 index → 它在旧列表的 index
- 在这个数组上算最长递增子序列（LIS）——它代表"新列表中哪些节点在旧列表里相对顺序已经正确"
- LIS 里的节点一个都不用移动，只把不在 LIS 里的节点插入到正确位置

**推演**：
头部插入 [A,B,C,D,E] → [X,A,B,C,D,E]：
- 头部扫描：A vs X ✗ → 第一轮就停（i=0）
- 尾部扫描：E✓ D✓ C✓ B✓ A✓ 一路吃到头（e1=-1, e2=0）
- 分流：i > e1 且 i <= e2 → 新列表剩 X，头部插入一次
- 结果：5 次 patch + 1 次插入，零移动——头尾扫描吃掉了整段没变的尾部
中间插入 [A,B,C,D,E] → [A,X,B,C,D,E]：
- 头部：A ✓，B vs X ✗ → 停（i=1）
- 尾部：E✓ D✓ → 停（e1=2, e2=3）
- 分流：旧剩 B,C，新剩 X,B,C → 进核心 diff
- 核心阶段：X 是新增，B、C 的映射值递增（在 LIS 里）→ 只插 X，B、C 零移动
完全反转 [A,B,C,D,E] → [E,D,C,B,A]：
- 头部：A vs E ✗ 第一轮就停；尾部：E vs A ✗ 第一轮就停
- 预处理完全没吃到 → 直接全量进核心 diff——预处理的收益在"顺序大体没变"的场景，反转这种它就无能为力，但那是真乱序的活
