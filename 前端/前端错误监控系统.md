1. 捕获：JS 运行时错误、Promise 未捕获、资源加载失败、框架（React/Vue）错误——分别靠什么 API？有哪些"沉默的错误"是这些 API 抓不到的？
	1. 全局兜底：window.addEventListener('error') 抓 JS 运行时错误；unhandledrejection 抓 Promise 未捕获。
	2. 资源加载失败：window.addEventListener('error', handler, true)——捕获阶段监听，判断 event.target 是 img/script/link 等标签
	3. 框架：Vue errorHandler ✓ 你说对了；React 是 error boundary
	4. 静默错误：跨域脚本无 crossorigin 属性时只给你一句 "Script error."——这就是"抓不到的沉默错误"
2. 上报：怎么上报才不拖垮性能和用户体验？上报时机、合并策略、用什么 API（想想页面卸载时怎么办）？
	1. 内存队列批量合并（攒 10 条或 10 秒一发）→ 采样率（10% 抽样）→ 页面卸载场景必须 navigator.sendBeacon（普通 fetch 在卸载瞬间会被浏览器中断）→ 经典方案 1x1 GIF 打点。
3. 定位：线上代码是压缩混淆的，怎么还原出源码位置？完整链路是什么？
	1. 发布时把 sourcemap 上传到监控平台（绝不上 CDN，防源码泄露）→ 错误带上行列号上报 → 后台服务端用 source-map 库把压缩后行列号映射回源码位置。
4. 聚合：100 万用户同一行代码报错，怎么避免后台收到 100 万条重复报警？靠什么做"错误指纹"？
	1. 错误信息（message + 堆栈 + 文件名 + 行列号）做 hash 指纹 → 后台按指纹去重，同一问题只报警一次，展示影响用户数曲线 → 按发布版本管理 issue 状态。
