## 按优先级复习计划

### P0：React 渲染机制（最大短板，已补主线）
- setState → updateQueue → 调度（MessageChannel 宏任务/调度周期合并）→ fiber reconcile → commit 全链路
- useState 值存 fiber.memoizedState 的 hook 链表（调用顺序 = 链表位置 → Hooks 规则根源）
- 双缓冲：current / workInProgress，可中断渲染的根基
- commit 三阶段：mutation(DOM 变) → useLayoutEffect(同步) → paint → useEffect(异步)
- 建议：写 50 行简化版 useState+调度器+双缓冲，写完才算懂

### P0：React 性能
- memo = props 浅比较；内联函数/对象让 memo 失效
- useCallback 依赖**不稳定就失效**（[rows] 每次新引用 → 每次新函数）
- 状态下沉设计 > memo 补丁（优化从状态归属开始）

### P1：HTTP 缓存（已补）
- 决策链：本地缓存？→ no-store/max-age(强缓存不发请求)/no-cache(协商) → If-None-Match(ETag 优先) → 304(空 body)/200(全量)
- 锚点：If-None-Match = "指纹匹配不上才给我新的"；304 = 空 body
- 工程联系：webpack contenthash = URL 变 = 新缓存条目

### P1：浏览器渲染
- 一帧：Style → Layout → Paint → Composite
- 触发深度：left=回流(L+P+C) / color=重绘(P+C) / transform+opacity=仅合成(C)
- 线程分工：主线程 = JS+样式+布局+绘制；栅格线程 = 栅格化；合成器线程 = 合成+滚动+transform/opacity 动画
- 图层模型：transform 动画不重新 paint（贴图内容不变只做矩阵变换）；图层占 GPU 内存，will-change 不能滥用
- 内容更新永远逃不开主线程（OffscreenCanvas 是终极解法）

### P1：Vue 边界（未补全）
- 解包规则：顶层 ref ✓ / 模板标识符 ✓(编译期 _unref) / **数组元素 ✗** / reactive 内嵌 ref 属性 ✓
- ref 实现：RefImpl 类 + 自带 dep，基本类型不走 Proxy
- diff：预处理(头尾) + newIndexToOldIndexMap + LIS（LIS 内不移动，移动次数最少）

### P2：系统设计（未补全）
- 前端监控 4 链路：捕获(onerror/unhandledrejection/资源捕获阶段/error boundary) → 上报(批量+采样+sendBeacon+1x1 GIF) → 定位(sourcemap 上传平台后台还原) → 聚合(错误指纹 hash + 按版本管理)
