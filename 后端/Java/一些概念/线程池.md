线程池的存在意义是把耗时的重建工作从请求线程剥离出去

### 缓存重建 线程池

正式业务代码中 一般 自定义 ThreadPoolExecutor 并交给 Spring 管理，参数按业务定
#### 关键点
1. 参数依据：缓存重建是 IO 密集型（DB + Redis），线程大部分时间阻塞在 IO，所以线程数可以大于 CPU 核数（参考 availableProcessors() * 2）；核心线程数小一点，避免低峰期浪费。
2. 必须用有界队列（ArrayBlockingQueue）：newFixedThreadPool 的 LinkedBlockingQueue 无界，高峰时任务堆积 = 隐性内存泄漏。
3. 自定义拒绝策略：缓存重建是"可丢弃"任务——丢一次没大碍，下次请求检测到逻辑过期再重建。所以常见选择是 CallerRunsPolicy（执行线程自己兜底重建，同时天然限流）或 DiscardPolicy，而不是默认 AbortPolicy 直接抛异常。
4. 有意义的线程名：出问题时能从 dump 里认出 cache-rebuild-N 线程。
5. 用 @Bean 注入，不要像现在这样在类里 new 出来——便于统一配置、监控和复用。
```java

@Bean("cacheRebuildExecutor")
public ThreadPoolExecutor cacheRebuildExecutor() {
    return new ThreadPoolExecutor(
        2,                                       // 核心线程数：CPU 核数附近即可
        Runtime.getRuntime().availableProcessors() * 2, // 最大线程数
        60, TimeUnit.SECONDS,                    // 非核心线程空闲回收
        new ArrayBlockingQueue<>(200),           // 有界队列，防止任务无限堆积
        new ThreadFactoryBuilder().setNameFormat("cache-rebuild-%d").build(),
        new ThreadPoolExecutor.CallerRunsPolicy() // 拒绝策略
    );
}

```

spring中一般靠配置
```yaml
# 用 Spring Boot 的 ThreadPoolTaskExecutor，且通过配置而不是手动 new：
# application.yml
spring:
  task:
    execution:
      pool:
        core-size: 2
        max-size: 8
        queue-capacity: 200
        keep-alive: 60s
      thread-name-prefix: cache-rebuild-
# 然后直接注入即可：
# @Resource
# private TaskExecutor taskExecutor;  // Spring Boot 自动配置的 bean
```
