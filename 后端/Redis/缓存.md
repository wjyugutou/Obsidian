## 缓存穿透

客户端请求的数据 缓存中没有, 数据库也没有, 每次都会进数据库

解决: 
1. 缓存空对象(null/"")
	1. 缺点
		1. 可能会造成短期不一致
2. 布隆过滤
	1. 实现
		1. 用谷歌现成的
		2. 客户端与 redis 直接加一层过, 不存在直接拒绝
		3. 本质 bitmap
	2. 缺点
		1. 实现复杂
3. 增加id复杂度,避免被猜
4. 做好数据校验
	1. id=0 过滤
5. 用户权限校验
6. 热点参数限流

## 缓存雪崩

同一时间段 大量缓存key 同时失效 或 redis 宕机, 大量请求直接到数据库

解决
1. 给key TTL 额外加 随机值
2. Redis 集群
3. 缓存业务添加降级 限流策略
4. 业务添加多级缓存


## 缓存击穿(热点key)

大量请求访问, 但是key 这时候失效了

解决
1. 互斥锁
	1. 某个线程获取锁 ,只有他能查库写缓存, 其他线程 循环 (等待-重试), 等 锁线程 写入缓存成功 
2. 逻辑过期
	1. <font color="#ff0000">需要数据预热</font>
	2. 不使用 redis提供的 expire, 我们自己存一个 expire 字段, 在代码逻辑中判断 是否过期, 
	3. 过期就开一个新线程 去 做拿锁-读库-写缓存, 当前线程返回旧数据
	4. 其他线程 请求过来发现 数据过期, 也有锁, 直接返回过期数据
